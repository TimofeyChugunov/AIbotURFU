# AIbotURFU

Первая локальная версия учебного помощника. Минималистичный интерфейс, три режима, история диалогов в браузере, панель администратора и база материалов PDF / DOCX / TXT. Сайт и модель запускаются локально; репозиторий содержит исходный код без базы пользователей, загруженных материалов и весов модели.

В правом верхнем углу чата и панели администратора есть переключатель ☾ / ☀ для светлой и тёмной темы. По умолчанию используется прежняя светлая тема. Выбор сохраняется в текущем браузере, действует при переходе между страницами и синхронизируется между вкладками этого сайта. Просмотр текста DOCX также поддерживает выбранную тему; встроенные средства браузера для PDF и TXT оформляются самим браузером.

## Аккаунты пользователей

Внизу бокового меню нажмите **«Вход / Регистрация»** (или откройте `/auth`). На вкладке **«Регистрация»** укажите уникальный Username, пароль и подтверждение пароля. После регистрации вход выполняется автоматически. В следующий раз используйте вкладку **«Вход»** с теми же Username и паролем.

Username: 3–32 символа, русские/латинские буквы, цифры, точка, дефис или подчёркивание. Регистр не влияет на уникальность и вход: `Student` и `student` — один аккаунт. Пароль: 8–128 символов, регистр учитывается. Пароли не хранятся открытым текстом: используется PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль для каждого пользователя.

Пользователи и сеансы находятся в таблицах `users` и `user_sessions` базы **`data/materials.sqlite3`**. Таблицы создаются автоматически при запуске, имеющиеся материалы сохраняются. Аккаунты и действующие сеансы переживают перезапуск сервера. Cookie входа действует 30 дней; кнопка **«Выйти»** отзывает текущий сеанс. В базе хранится хеш токена, cookie недоступна JavaScript (`HttpOnly`, `SameSite=Strict`). Пароли и токены не передаются локальному ИИ.

История диалогов пока хранится **в этом браузере**, отдельно для каждого аккаунта и гостя. При выходе личная история перестаёт отображаться, при повторном входе в том же браузере возвращается. Между устройствами история не синхронизируется. Удаление данных браузера удалит эту историю, но не аккаунт. Гостевой чат и материалы доступны без регистрации. Вход администратора через `/admin` остаётся отдельным: обычная регистрация не даёт права загружать и удалять материалы. Восстановление и смена пароля пока не реализованы.

База содержит данные пользователей: резервируйте `data/` целиком и учитывайте синхронизацию OneDrive. Текущий сервер рассчитан на localhost; для размещения с внешним доступом потребуется HTTPS и соответствующая настройка cookie.

## Запуск в Windows PowerShell

Чтобы получить проект на другом компьютере:

```powershell
git clone https://github.com/TimofeyChugunov/AIbotURFU.git
cd AIbotURFU
```

Нужны Python 3.10+ и [Ollama](https://ollama.com/download/windows). Модель устанавливается отдельно командой `ollama pull qwen3:8b`. База `data/materials.sqlite3` создаётся при первом запуске. GitHub хранит код и сам по себе не запускает Python-сервер и локальный ИИ.

Откройте терминал **в этой папке**:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Задайте пароль администратора скрытым вводом (сохраняется только в окружении этого терминала):

```powershell
$adminSecret = Read-Host 'Придумайте пароль администратора' -AsSecureString
$env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminSecret).Password
$env:AI_MODE = 'ollama'
.\.venv\Scripts\python.exe server.py
```

Откройте **http://127.0.0.1:3000**. Панель администратора: **http://127.0.0.1:3000/admin**. Остановка — Ctrl+C. Порт можно изменить переменной `PORT`. Сервер слушает только `127.0.0.1`. Активация виртуального окружения и изменение ExecutionPolicy не нужны. Для повторного запуска можно использовать `./start.ps1`, если это разрешено настройками PowerShell.

Без `ADMIN_PASSWORD` чат и просмотр списка работают, вход администратора отключён. Пароль не имеет значения по умолчанию. Сеанс администратора действует 8 часов или до перезапуска сервера.

## Деморежим и настоящий ИИ

В режиме настоящего ИИ можно вести обычный диалог и спрашивать об искусственном интеллекте, машинном обучении, нейросетях и других учебных темах без загрузки документов. Уточнения вроде «объясни проще», «а чем он отличается?» и «приведи пример» учитывают последние реплики выбранного диалога. История ограничена контекстом модели: до 12 недавних сообщений, длинные ответы сокращаются, бесконечной памяти нет. Кнопка «Новый диалог» начинает новую беседу.

Методички нужны для ответов по конкретным документам и нормативным требованиям. Для общих вопросов отсутствие файлов не должно мешать ответу. Проверка реального диалога без материалов: `.\.venv\Scripts\python.exe tests/dialogue_smoke.py` (два локальных запроса к Qwen, временная база).

### Локальный ИИ: Ollama + Qwen3 8B

Сайт по умолчанию использует локальную модель **qwen3:8b** через Ollama на `127.0.0.1:11434`. API-ключ и платный тариф не нужны. Браузер обращается к Python-серверу, а тот передаёт вопрос и найденные фрагменты модели на этом компьютере. Облачные модели в этом адаптере отключены.

1. Установите [Ollama для Windows](https://ollama.com/download/windows) и запустите её.
2. Откройте новый терминал и скачайте модель: `ollama pull qwen3:8b` (около 5,2 ГБ).
3. В папке проекта выполните **`.\start-local.cmd`**. Этот запуск явно выбирает Ollama, даже если в терминале остался `AI_MODE=demo`.
4. Откройте http://127.0.0.1:3000. Статус **«Qwen · локально»** означает, что Ollama отвечает и модель установлена. Проверка статуса не выполняет генерацию.

Можно запускать и прежней командой `.\.venv\Scripts\python.exe server.py`. Если в текущем терминале ранее задавался `AI_MODE`, перед запуском выполните `$env:AI_MODE = 'ollama'`. Пароль администратора задаётся по инструкции выше; `start-local.cmd` сохраняет его из окружения.

Первый ответ может потребовать загрузки модели в видеопамять. Тайм-аут — 180 секунд, одновременно выполняется один запрос; если модель занята, сайт предлагает повторить запрос. Контекст ограничен 8192 токенами, до трёх фрагментов документов и сокращённой историей. Длинные рассуждения отключены. При ошибке Ollama сайт сообщает о ней, без подмены шаблоном и без обращения к OpenAI.

Команды диагностики: `ollama list` — установленные модели; `ollama ps` — загруженная модель и использование CPU/GPU; `nvidia-smi` — состояние видеокарты. При нехватке памяти закройте приложения, использующие GPU. Для освобождения памяти после работы: `ollama stop qwen3:8b`. Модель хранится вне проекта, обычно в `%USERPROFILE%\.ollama\models`.

Для проверки настоящего ответа по тестовому документу: `.\.venv\Scripts\python.exe tests/ollama_smoke.py`. Этот сценарий использует временную базу, не изменяет ваши материалы и проверяет уникальный код из документа и ссылку `[1]`. Во время обычных unit-тестов модель не вызывается.

Для переноса на другой компьютер понадобятся приложение, база `data/` и Ollama с той же моделью. Студентам устанавливать Ollama не нужно. Сам API Ollama не следует публиковать в интернет — с ним работает только сервер приложения.

### Деморежим и облачный API

Чтобы явно включить **деморежим**, задайте `$env:AI_MODE = 'demo'` перед запуском. Если найдены материалы по вопросу, он показывает до трёх выдержек со ссылками на документы. Для вопроса о введении дополнительно выводятся два заранее написанных общих совета по работе с требованиями — это не требования ГОСТ. Если совпадений нет, сайт сообщает об этом и показывает шаблон выбранного режима. Это **не ИИ**, произвольные ответы не генерируются. Сетевых обращений к провайдеру в деморежиме нет.

Для настоящих ответов реализовано серверное подключение к OpenAI Responses API. Нужны собственный API-ключ, доступная вашему проекту текстовая модель и доступ к API. Настоящие ответы без ключа не тестировались. Имя модели указывается явно — приложение не подменяет его автоматически.

Остановите сервер, затем в том же PowerShell:

```powershell
$apiSecret = Read-Host 'API-ключ OpenAI' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $apiSecret).Password
$env:OPENAI_MODEL = Read-Host 'ID доступной вашему проекту модели Responses API'
$env:AI_MODE = 'live'
.\.venv\Scripts\python.exe server.py
```

Получить ключ и проверить доступные модели можно в своём проекте OpenAI Platform. Храните ключ только на сервере, в переменной окружения или менеджере секретов. Не вставляйте ключ в HTML, JavaScript, переписку или команды, сохраняющие его в истории. Не добавляйте его в репозиторий. `.env` исключён из Git, но приложение **не читает `.env` автоматически**: секреты передаются через окружение. Не создавайте `.env` с ключом в синхронизируемой папке OneDrive. После работы закройте терминал или удалите переменные:

```powershell
Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:ADMIN_PASSWORD -ErrorAction SilentlyContinue
```

В режиме `live` при отправке сообщения **в OpenAI передаются вопрос, до 12 последних сообщений и до 5 найденных текстовых фрагментов материалов**. Оригиналы документов отдельно не отправляются. Запрос использует `store: false`; это не обещание отсутствия всех журналов у провайдера. Учитывайте правила обработки данных вашего проекта. Вызовы API могут быть платными. Ошибки ключа, квоты или сети показываются как ошибки — подмена ответом из деморежима не выполняется.

Официальная документация: [аутентификация и хранение ключей](https://developers.openai.com/api/reference/overview), [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).

## Материалы

Войдите на `/admin`, выберите или перетащите файлы и нажмите «Загрузить материалы». База SQLite `data/materials.sqlite3` хранит оригиналы и извлечённый текст. Для удаления используйте кнопку рядом с документом. При удалении материал больше не используется в новых запросах; уже существующие ответы в истории браузера не меняются.

Все загруженные администратором файлы доступны пользователям этого сервера без входа: в чате нажмите **«Учебные материалы»**, затем **«Открыть»** или **«Скачать»**. PDF открывается средствами браузера, TXT — как текст в UTF-8, DOCX — на странице с извлечённым текстом (без исходной вёрстки). При скачивании всегда передаётся исходный файл с исходным именем, включая кириллицу. Уже загруженные файлы также доступны — повторная загрузка не нужна. После удаления администратором ссылки на файл перестают работать. Загрузка и удаление по-прежнему требуют входа администратора.

Общий доступ действует в пределах одного экземпляра сервера и его базы `data/`. Текущий запуск на `127.0.0.1` доступен только на этом компьютере. Доступ с других компьютеров потребует отдельной настройки сервера или размещения; эта версия по-прежнему работает локально.

- PDF с текстовым слоем — до 200 страниц; сканы требуют предварительного OCR. Защищённые паролем файлы отклоняются.
- DOCX: читаются абзацы и таблицы; изображения и сложная вёрстка не анализируются.
- TXT: UTF-8 и Windows-1251.
- Ограничения: 10 МБ на файл, 500 000 извлечённых символов; распакованный DOCX — до 40 МБ.

Поиск по материалам локальный, без векторной базы: текст разбивается на фрагменты, слова нормализуются по простым правилам русского языка, совпадения ранжируются по редкости слов и покрытию вопроса. «Введение», «во введении» и «введения» ищутся как одна тема. Короткие уточнения учитывают последний вопрос студента. Это лексический поиск, а не полноценное понимание смысла: при слабом результате уточните формулировку.

В режиме ИИ найденные фрагменты передаются модели с инструкцией отвечать по материалам, отделять требования от советов и указывать источники `[1]`, `[2]`. Под ответом можно раскрыть найденную выдержку и открыть документ. Фрагменты в списке — переданный контекст, а не гарантия подтверждения ответа; проверяйте цитаты. Номера страниц пока не сохраняются. Если в материалах нет нужного требования, номера или редакции ГОСТа, помощник должен сообщить о нехватке данных, а не придумывать нормативные требования. Для проверки загрузите нужную методичку или текст стандарта через `/admin`, затем задайте вопрос в чате. Уже загруженные материалы участвуют в поиске автоматически.

Режимы отчёта и презентации дают текстовый план, не создают готовые DOCX/PPTX. Конкретная просьба вроде «дай пару советов» имеет приоритет над полным планом.

История хранится в localStorage текущего браузера (до 30 диалогов, по 80 сообщений на аккаунт или гостя). Очистка — кнопка рядом с «Недавние диалоги», только для текущего аккаунта. Вход и регистрация доступны на `/auth`. Доступ к чату, просмотру и скачиванию материалов разрешён всем локальным пользователям, загрузка и удаление доступны администратору.

**Папка проекта находится в OneDrive:** приложение само ничего не публикует, но OneDrive может синхронизировать `data/` и историю резервных копий. Для строго локального хранения приостановите синхронизацию этой папки или перенесите проект вне OneDrive. Сервер предназначен для личной локальной работы, не для размещения в интернете.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check public/app.js
node --check public/admin.js
```

Дополнительно можно повторить браузерный сценарий в установленном Microsoft Edge (без скачивания браузера):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tests/browser_check.py
.\.venv\Scripts\python.exe tests/accounts_browser_check.py
```

Он проверяет три режима, историю, загрузку всех форматов, удаление и вход/выход; использует временную базу и деморежим, сохраняет снимки в `artifacts/`. Реальные API-вызовы не выполняет.

Приложение использует Python 3.10+ и две библиотеки чтения документов. Node.js нужен только для необязательной проверки синтаксиса JavaScript. Сборка интерфейса не требуется. Все стили и скрипты локальные, внешних шрифтов и CDN нет.
