# AIbotURFU: быстрый старт для разработчиков

Python + обычные HTML/CSS/JS, локальная **Qwen3 8B через Ollama**, SQLite. Работают диалоги, поиск по методичкам, аккаунты, управление пользователями, личная проверка DOCX и экспорт примечаний Word. Поиск лексический; дообучения, embeddings и векторной базы пока нет. Пользовательская инструкция — в [README.md](README.md).

## Установка и запуск (Windows PowerShell)

Нужны Git, Python 3.10+ и [Ollama](https://ollama.com/download). API-ключ, Node.js и сборка интерфейса для локального запуска не требуются.

```powershell
git clone https://github.com/TimofeyChugunov/AIbotURFU.git
cd AIbotURFU
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
ollama pull qwen3:8b
```

Запустите приложение Ollama. Для доступа к админке задайте пароль в текущем терминале, затем запустите сайт:

```powershell
$adminSecret = Read-Host 'Пароль администратора' -AsSecureString
$env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminSecret).Password
.\start-local.cmd
```

Чат: http://127.0.0.1:3000, регистрация: `/auth`, админка: `/admin`. Остановка — Ctrl+C. Повторный запуск: Ollama и `.\start-local.cmd`; в новом терминале пароль администратора задаётся заново. Без него чат работает, вход администратора отключён.

Для разработки без модели используйте явно обозначенный деморежим:

```powershell
$env:AI_MODE = 'demo'
.\.venv\Scripts\python.exe server.py
```

В демо доступны программные проверки DOCX, но оценка содержания ИИ не выполняется. `start-local.cmd` всегда выбирает Ollama и `qwen3:8b`; `.env` автоматически не читается. Облачный режим и переменные окружения описаны в README.

## Где что менять

| Файл | Назначение |
| --- | --- |
| `server.py` | HTTP API, SQLite, общие материалы, инструкции ИИ и авторизация |
| `local_ai.py` | Ollama, ограничения контекста и генерации |
| `retrieval.py` | Фрагменты методичек, лексический поиск и уточнения |
| `docx_review.py` | Разбор DOCX, проверки, выборка для ИИ, привязка и экспорт замечаний |
| `docx_fonts.py` | Шрифты по символам, стилям и теме DOCX |
| `accounts.py` | Регистрация, хеширование паролей и сеансы |
| `public/app.js`, `public/style.css` | Чат, история, вложения и оформление |
| `public/admin.js`, `public/auth.js`, `public/theme.js` | Админка, вход и темы |
| `tests/` | Unit-, браузерные проверки и сценарии с настоящей моделью |

Общий запрос: вопрос и история → поиск по общим материалам → контекст модели → ответ с источниками. Общие вопросы работают без документов. Материалы PDF, DOCX и TXT загружаются через `/admin`, доступны всем пользователям для просмотра и скачивания.

Личный DOCX: разбор в памяти → программные наблюдения → выборка текста и найденных требований для ИИ → проверка цитат замечаний → ответ. Оформление проверяет код, смысловую связность — модель. Преобладающий шрифт определяется по основному тексту отдельно от приложений, таблиц и кода; это не норматив ГОСТ. Учитываются отдельные шрифты кириллицы/латиницы и несколько отличий в одном абзаце. Проверки нецензурной лексики и подозрительных латинских вставок ограничены правилами, допустимые технические термины учитываются.

## DOCX: API и ограничения

- `POST /api/chat`: `message`, `mode` (`explain`, `report`, `presentation`), `history`; необязательное `attachment: {name, content}` с именем `.docx` и содержимым Base64. В ответе — `text`, `sources`, `demo` и при вложении `document_review` с наблюдениями, `source_hash` и проверенными `ai_comments`.
- `POST /api/chat/document/export`: тот же `attachment` и `feedback: {source_hash, summary, comments, demo}`. Возвращает бинарный DOCX без повторного вызова ИИ; программа заново рассчитывает свои наблюдения. Хеш связывает отзыв с исходником.
- Замечания ИИ привязываются по номеру абзаца и буквальной цитате. Категории: `recommendation` — светло-жёлтая, `important` — красная, `improvement` — светло-зелёная. Заливка находится внутри стандартных примечаний Word. Исходный текст и существующие примечания сохраняются.
- Лимиты: файл до 10 МБ, распакованный DOCX до 40 МБ, 4000 непустых абзацев, 500 000 символов. DOC и PDF в личных вложениях не поддерживаются; для общей библиотеки PDF поддерживается.
- Длинные работы передаются модели выборочно, с приоритетом абзацев с находками. Вёрстка страниц, изображения, формулы, сноски и колонтитулы не проверяются. Полнота логической и языковой проверки не гарантируется; нарушения ГОСТ требуют подтверждённого источника.

Примеры запросов и проверок экспорта: [tests/test_app.py](tests/test_app.py), [tests/docx_chat_smoke.py](tests/docx_chat_smoke.py). Для новой проверки добавляйте пример с ожидаемым замечанием и пример допустимого текста.

## Данные и доступ

`data/materials.sqlite3` создаётся автоматически: общие материалы, аккаунты и сеансы. Пароли хранятся как солёные хеши PBKDF2; вход администратора отдельный. В `/admin` доступны список пользователей, сброс пароля и удаление аккаунта; обе операции отзывают сеансы пользователя.

История хранится в localStorage отдельно для аккаунтов и гостя, включая ответы и замечания. Доступно удаление отдельных чатов. Личные DOCX хранятся в памяти вкладки, не попадают в SQLite и отправляются с каждым вопросом о файле. После перезагрузки исходник нужно прикрепить заново; для скачивания сохранённого отзыва требуется тот же файл. В Ollama анализ локальный, в облачном режиме выбранный текст передаётся внешнему API.

Рабочая база, вложения, секреты, модель и `artifacts/` не должны попадать в Git. Создавайте свои тестовые данные; резервную копию `data/` делайте после остановки сервера. Учитывайте отдельную синхронизацию OneDrive.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Браузерные сценарии используют установленный Microsoft Edge, временную базу и деморежим; модель не вызывается:

```powershell
.\.venv\Scripts\python.exe tests/browser_check.py
.\.venv\Scripts\python.exe tests/accounts_browser_check.py
.\.venv\Scripts\python.exe tests/admin_users_browser_check.py
.\.venv\Scripts\python.exe tests/docx_chat_browser_check.py
```

С работающей Ollama и `qwen3:8b` запускайте последовательно:

```powershell
.\.venv\Scripts\python.exe tests/dialogue_smoke.py
.\.venv\Scripts\python.exe tests/ollama_smoke.py
.\.venv\Scripts\python.exe tests/docx_chat_smoke.py
.\.venv\Scripts\python.exe tests/docx_context_smoke.py
```

Они проверяют настоящий диалог, RAG, анализ DOCX с экспортом и смысловые вставки. Ответы модели могут различаться. Синтаксис изменённого JS при наличии Node.js проверяйте командой `node --check путь/к/файлу.js`.

## Дальнейшая работа

1. Собрать набор вопросов и DOCX с ожидаемыми ответами, источниками и замечаниями; оценивать пропуски, ложные срабатывания и время ответа.
2. Улучшить RAG и проверку работ: метаданные страниц и требований, индекс, embeddings, гибридный поиск, обработка длинных DOCX.
3. Решать вопрос дообучения по результатам оценки; обучение потребует отдельного инструментария и датасета.
4. Подготовить размещение: HTTPS, cookie, адрес ИИ, очередь запросов и резервные копии.

Сейчас сервер работает только на localhost, адрес Ollama фиксирован в `local_ai.py`, одновременно выполняется одна генерация. Готовой конфигурации публичного размещения нет. Разрабатывайте в отдельных ветках и передавайте изменения через Pull Request.
